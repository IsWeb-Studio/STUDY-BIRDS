# COVEY assistant update — 2026-10-30

The app and server use the same reviewed-help contract. The compatible wire/navigation version stays `2026.10.23.3`; the content revision is independently `2026.10.30.1`. Installed clients do not need a protocol upgrade merely because help text changed.

## Updated product knowledge

The guide contains 71 reviewed bilingual records. Updated navigation, community publishing and filters, profile tiles, stories, streak and points rules, profile photos, notifications and support. Added focused records for the Home menu, blocked users/unblocking, recognition cards, comments/reactions, administration posts, public profiles, removed microphone controls, local cache and persistent AI consent. Legacy wording remains searchable as an alias when useful; answers use current labels.

The server returns `knowledgeRevision` on config, history and replies, and saves it with each assistant answer. Replies from an older guide remain stored but are replaced with a notice in returned history; outdated actions/details are hidden. Old topics cannot be reused for followups without the current content revision.

Ambiguous questions now receive a local clarification listing the approved topics. They no longer fail because a provider is absent or ask a model to select a topic from IDs without the question. Clear help uses reviewed text; the existing personal application-status path reads only the authenticated student's records. No external model receives this help flow's conversation or account records.

The app disclosure and published privacy text describe this behavior. Consent version 2 asks once for the changed disclosure and then remembers acceptance per account/device. It is not requested on every AI visit.

## Verification and updates

From the repository root, verify reviewed sources:

```powershell
node server/scripts/assistant-knowledge-tools.cjs --mobile-root app --website-root client
```

CI runs this check before backend regression tests. Source hashes normalize CRLF/LF for Windows/Linux consistency. After reviewing relevant product changes and updating the guide, explicitly record a new reviewed snapshot:

```powershell
node server/scripts/assistant-knowledge-tools.cjs --mobile-root app --website-root client --record-reviewed-snapshot
```

Do not refresh the snapshot merely to suppress a failure. Update bilingual guidance, sources, aliases and tests first. The snapshot broadly covers the mobile, server and web sources; not every hash change implies a semantic help change.

## Deployment

Deploy the updated `server/` and matching `client/` on Render from Islam's canonical main. The app build contains matching content-revision metadata and the corrected disclosure. Do not deploy from a stale copy of `D:\work\studybirds_web` without synchronizing the assistant files. The local server mirror is synchronized as part of this change; credentials and provider settings are not changed.

After deployment, authenticated `/api/assistant/config` must return `enabled: true`, `scopePolicy: studybirds-only-v1`, `responseFormat: verified-help-v1`, `knowledgeVersion: 2026.10.23.3`, and `knowledgeRevision: 2026.10.30.1`. Test one current-product question and one ambiguous question in the app. Existing deployed Render state is not asserted by local tests.

## Deliberate limits

This is app guidance, not general-purpose generation or an agent that performs account actions. It does not invent current invoice balances, consultation times, fees or admission outcomes. Payments guidance directs users to the authoritative invoice screen. Only the existing caller-scoped application-status reader supplies live personal summaries. Other live data tools, richer role-specific workflows and arbitrary general questions are not introduced by this update.
