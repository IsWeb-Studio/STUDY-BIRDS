# Phase 6 — جاهزية Android QA وإعداد البيئة المعزولة

21 أكتوبر 2026. الحالة: **أُنجز دعم الإعداد المحلي؛ اختبار الجهاز وبناء QA متوقفان لغياب موارد معزولة متحققة**. لا جاهزية إنتاج ولا نجاح جهاز حقيقي مثبت. لم تُكرر مراجعة التخزين أو تُنفّذ عمليات تنظيف إضافية.

## النتيجة المحلية

عُدّل تطبيق النشر في `D:\work\studybirds_session_release\app` فقط لإضافة إعداد QA صريح. الإنتاج يحتفظ بعنوانه الافتراضي ومعرفاته وإعداداته وسلوك خدماته الحالي. التطبيق الأساسي ومصدر السيرفر والموقع لم تُعدّل ضمن هذا العمل؛ أُضيفت التقارير إلى docs في التطبيق الأساسي.

`APP_ENV=qa` لا يستعمل fallback إلى API الإنتاج. يحتاج QA_API_BASE_URL مستقلًا وصالحًا وQA_RESOURCES_VERIFIED بعد تحقق المالك الفعلي. نقص الإعداد أو خطأ APP_ENV يوقف البدء قبل استعادة الجلسة والخدمات. نقل ApiClient يمنع الخروج من أصل QA وتعقب HTTP redirects، ويفحص الوجهات الخارجية في ردود API الناجحة. resolver المستندات يتحقق من الوجهة أيضًا.

في QA تُعطّل Google وApple وOneSignal وSentry وPostHog وخدمة العملات الخارجية؛ لا تكفي أعلام التحليلات القديمة لتفعيلها. لم تُستبدل أسرار أو معرفات الإنتاج ولم تُنشأ credentials. التفاصيل والحدود في [إعداد QA](PHASE6_QA_CONFIGURATION.md).

## التكاملات والموارد الناقصة

لم يُقدَّم أو يُتحقق من API QA أو قاعدة MongoDB/JWT secrets منفصلة أو تخزين أو حسابات مصطنعة أو mail sink. لم يبدأ backend ولم تُجرَ اتصالات أو عمليات seed أو تغيير قاعدة/مزود.

Google/OAuth وOneSignal/FCM وtelemetry تحتاج مشاريع ومفاتيح QA منفصلة ودعم إعداد لاحقًا إن أُريد اختبارها؛ هي محجوبة في وضع QA الحالي. مستندات Cloudinary الخارجية محجوبة أيضًا إلى أن يُراجع مسار تخزين/تنزيل QA معزول دون تغيير صامت للعقد الحالي. لا تهيئة Firebase Dart مباشرة رُصدت؛ OneSignal وML Kit native لا تعنيان انعدام اتصالات native. OCR يستخدم ML Kit المحلي وMRZ محليًا، لكن لم يُختبر على جهاز.

توجد روابط وصور ومتصفحات ووسائط native لا تمر كلها عبر ApiClient. هذا الدعم **ليس جدار شبكة شاملًا**. يلزم ملف Android جديد أو جهاز معزول دون بيانات إنتاج، وقائمة egress تسمح بوجهات QA المقبولة فقط، ومراجعة merged manifest وروابط الوسائط قبل التشغيل. لم يُغيّر applicationId أو التوقيع أو مفاتيح التخزين؛ لا تُثبّت النسخة على ملف يستعمل التطبيق الإنتاجي. لا توضع QA_RESOURCES_VERIFIED=true لتجاوز هذه الحواجز.

## الفحوص الفعلية

كل أوامر Flutter من تطبيق النشر باستخدام `C:\src\flutter\bin\flutter.bat` و`--no-pub`، دون تثبيت تبعيات أو مزود خارجي:

- القبول الافتراضي: **44 حالة ناجحة، exit 0**. يشمل السياسات الجديدة ومسارات المستندات وGoogle password gate وlogin notification gate وتفضيلات الحساب الحالية.
- وضع QA ناقص الإعداد، حتى مع أعلام تفعيل Sentry/analytics: **25 حالة ناجحة، exit 0**. يثبت التوقف المبكر وحجب SDKs/العملات والوجهات غير المسموحة وفق نطاق الاختبارات، مع MockClient/channel mocks دون مزود حي.
- عميل API الفعلي مع عنوان `.invalid` وMockClient: **3 حالات ناجحة، exit 0**. اختيار QA بدل API_BASE_URL الإنتاجي، رفض رابط وسائط خارجي في الرد، ورفض تحويل رابط مستند للإنتاج. راية التحقق في هذه المجموعة fixture اختبار فقط.
- اسم بيئة غير معروف `APP_ENV=qaa`: **حالة واحدة ناجحة، exit 0**؛ لا fallback للإنتاج.
- هذه مجموعات تنفيذ قد تعيد اختبارات سياسة مشتركة؛ لا تعني 73 سيناريو مستقلًا فريدًا.
- `flutter analyze --no-pub`: **exit 1، 275 معلوماتية، صفر تحذيرات وصفر أخطاء**. بقي الدين السابق نفسه، ولم تُعطّل قواعد أو تُخفّف checks؛ ليس تحليلًا نظيفًا.
- `git diff --check` في المستودعين: exit 0.

فشل التشغيل الأول للاختبارات قبل التصحيح: 22 حالة نجحت و6 إخفاقات تحميل بسبب تحويل baseUrl من const، واستعمال await مع main ذي توقيع void. أُعيد const-compatible API وخُصّص التحقق للنقل/البدء، وصُحّح استدعاء الاختبار. السجل محفوظ؛ نتائج القبول النهائية أعلاه بعد الإصلاح. أول تحليل متداخل مع تلك التغييرات سجّل 279 معلوماتية؛ التحليل النهائي المستقر 275.

لم تُجرَ regression suites جديدة للسيرفر والموقع لأن مصدرهما والعقود لم تتغير؛ لا تُنسب نتائج المراحل السابقة إلى تنفيذ Phase 6.

## المساحة والبناء

بدأ العمل بنحو 6.314 GiB حرة على D. بعد checkpoints وتجميع الاختبارات المحلية بلغ القياس **6,342,692,864 بايت، نحو 5.907 GiB**؛ القياس الأخير الدقيق محفوظ في PHASE6_VALIDATION.json. لا تنظيف إضافي.

**لم يُبنَ APK QA جديد** ولم يُنفّذ flutter build. السبب الأساسي غياب موارد QA المتحققة، والمساحة النهائية كذلك أقل قليلًا من هامش 6 GiB التخطيطي. لا يُشغّل بناء الآن. APK debug القديم محفوظ وبصمته مطابقة، لكنه يستخدم إعداد المرحلة السابقة المستضاف ولا يصلح بدل APK QA جديد.

## سلامة العمل

قبل التعديل حُفظ checkpoint خاص بـPhase 6: ‏564 ملفًا للتطبيق الأساسي و1,167 لنسخة النشر، مع SHA-256 وGit HEAD/status وbinary diffs. checkpoints القديمة وعلاقات worktree محفوظة. تغييرات المصدر محددة في ثمانية ملفات قائمة لتوصيل guards، وملفين جديدين للإعداد/النقل، وأربعة ملفات اختبارات جديدة. لم تتغير auth contracts أو ملكية الوصول أو signing أو Gradle أو dependency manifests/locks.

## ما يلزم قبل الجهاز

1. يوفّر المالك API وDB وJWT secrets وتخزينًا وmail sink وحسابات مصطنعة، ويتحقق من فصلها دون استخدام إنتاج.
2. يُعزل ملف الجهاز وخروج الشبكة ويُراجع native/media/browser؛ تبقى الخدمات الخارجية المحجوبة NOT TESTED حتى إعداد مشاريع QA مستقلة ودعمها.
3. تُراجع مشكلة روابط التخزين المعزول وتُستكمل اختبارات الوصول؛ لا يُفعّل مزود الإنتاج لإنجاح الاختبار.
4. يُعاد قياس المساحة وتوفير هامش البناء، وحفظ APK القديم قبل أي كتابة لمساره. لا تنظيف آخر دون تفويض.
5. بعد ذلك فقط يُعتمد config، ويُبنى APK QA جديد وتُسجّل بصمته وdefines وmanifest ثم يُثبت على ملف الاختبار المعزول.
