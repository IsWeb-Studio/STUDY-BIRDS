# Phase 6 — إعداد QA صريح وآمن

21 أكتوبر 2026. دعم محلي فقط داخل تطبيق النشر `D:\work\studybirds_session_release\app`. لم تُجهّز بيئة خارجية ولم تُستخدم بيانات اعتماد أو قاعدة بيانات أو نقطة إنتاج. التطبيق الأساسي في `D:\work\studybirds_app\study_birds_app-main` لم يُزامَن مع نسخة النشر.

## ما أُضيف

- `APP_ENV` يقبل `production` افتراضيًا أو `qa` حرفيًا. القيم الأخرى توقف البدء؛ لا يُفترض أنها production.
- في QA لا يُستخدم `API_BASE_URL` ولا العنوان المستضاف الافتراضي؛ يلزم `QA_API_BASE_URL` مستقل وصريح، بصيغة HTTPS، ومسار `/api`، دون userinfo أو query أو fragment أو backslash.
- تُرفض أسماء الإنتاج المعروفة ومزوّدو الإنتاج المعروفون، بما في ذلك فروع نطاقاتهم والنقطة النهائية في اسم المضيف. هذه قائمة منع إضافية وليست دليلًا على أن أي نطاق آخر معزول.
- يلزم أيضًا `QA_RESOURCES_VERIFIED=true`. هذه **إفادة صريحة بعد تحقق المالك** من API وقاعدة البيانات والتخزين والحسابات والملف المحلي وخروج الشبكة، وليست فحصًا آليًا أو تصريحًا يمكن وضعه الآن لتجاوز المتطلبات.
- يُفحص الإعداد عند بدء التطبيق قبل Sentry واستعادة الجلسة والخدمات. الإعداد الناقص أو الخاطئ يعرض شاشة توقف محلية عامة دون طباعة بيانات حساسة.
- يعيد النقل المدار بواسطة ApiClient التحقق من الإعداد، ويسمح فقط بأصل QA المختار، ويعطّل اتباع HTTP redirects ويرفض ردود 3xx. لا تعبر ترويسة التفويض إلى أصل آخر عبر هذا النقل.
- تُرفض الوجهات الخارجية المطلقة داخل ردود API الناجحة قبل تحويلها إلى بيانات واجهة/وسائط. يتم فحص الوجهة أيضًا في document resolver.
- Google وApple وOneSignal وSentry وPostHog ومزوّد العملات الخارجي **معطّلة في QA**. لا توجد في هذه المرحلة طريقة لتفعيلها بمفاتيح إنتاج أو بوضع SENTRY_ENABLED=true أو POSTHOG_API_KEY. تظل متاحة وفق السلوك القديم في production.

لم تُستبدل معرّفات الإنتاج أو تُحذف. بقي `ApiClient.baseUrl` ثابتًا وقت الترجمة لحماية المستهلكين الحاليين؛ التحقق الفعلي يحدث قبل الخدمات وعند إنشاء النقل. لا تغييرات على API contracts أو أدوار المستخدمين أو خوارزمية تسجيل الدخول أو TLS pinning أو إعدادات التوقيع أو Gradle.

## التكاملات التي روجعت

- **API والمصادقة:** العنوان الافتراضي الحالي مستضاف على Render. يظل افتراضيًا للإنتاج فقط. QA يحتاج backend منفصلًا وJWT secrets مختلفة وحسابات مصطنعة. لم يبدأ السيرفر ولم تُقرأ قيم .env الحقيقية.
- **Google:** web client ID ثابت في AppConfig وiOS client ID يأتي من define. هذه معرفات عميل وليست كلمات مرور. المسار الأصلي يرسل credential إلى `/auth/google`. معطّل في QA؛ اختباره يحتاج مشروع OAuth وclient IDs وتسجيل package/signature مستقلين، ودعم إعداد منفصل لاحقًا.
- **Apple:** التكامل الموجود معطّل في QA قبل استدعاء SDK. يلزمه إعداد QA مستقل إن أُدرج في نطاق لاحق؛ Android QA الأساسي لا يفترض نجاحه.
- **OneSignal وFCM:** التطبيق يملك OneSignal app ID ثابتًا، والسيرفر يستخدم ONESIGNAL_APP_ID وONESIGNAL_REST_API_KEY. لا يُهيأ SDK بواسطة كود QA. يلزم مشروع QA مستقل وتهيئة FCM/جهاز اختبار منفصل قبل اختبار push الحقيقي. تغيير ID وحده ليس عزلًا كافيًا.
- **Firebase:** لم تُرصد Firebase Dart dependencies أو تهيئة Firebase مباشرة أو google-services.json في مصدر Android الحالي. المصادقة Google ليست Firebase Auth. OneSignal قد يستخدم FCM كتبعيات native، وML Kit موجود؛ غياب Firebase Dart لا يثبت انعدام اتصالات Google على الجهاز.
- **رفع المستندات والوسائط:** الرفع من التطبيق عبر API، والسيرفر يستعمل Cloudinary بما فيه تخزين مستندات authenticated وروابط تنزيل موقّعة. يلزم حساب/مساحة QA مستقلة أو خدمة تخزين QA يوافق عليها المالك. الحارس الحالي يرفض روابط Cloudinary الخارجية في QA؛ لا يُدّعى نجاح تنزيل المستندات أو الفيديو الحقيقي قبل إكمال تصميم الوصول المعزول واختباره. لا تغيير صامت لعقد روابط المستندات الحالي.
- **Email وOTP:** السيرفر يعتمد Brevo/SMTP، مع تكاملات SMS/WhatsApp منفصلة. يلزم mail sink وعناوين اختبار وقنوات sandbox دون مراسلة أشخاص حقيقيين. يجب ضبط SITE_URL وEMAIL_ASSET_ORIGIN وCLIENT_URL صراحة؛ مصدر السيرفر يحتوي fallback لروابط الإنتاج في البريد وواجهة الموقع. لم تُغيّر هذه الإعدادات أو تُرسل رسالة.
- **OCR وجواز السفر:** PassportScanner/Kotlin يستخدم ML Kit TextRecognition المحلي مع dependency bundled `com.google.mlkit:text-recognition:16.0.1`، والتحقق من MRZ محلي؛ الرفع يحدث بعد المراجعة عبر API. لا مفتاح OCR سحابي مباشر رُصد في هذا المسار. يلزم جواز مصطنع، تحقق الجهاز والأذونات، ومراجعة خروج الشبكة native؛ لم يُختبر OCR على جهاز.
- **Sentry وanalytics:** DSN ثابت في AppConfig، وPostHog host ثابت ومفتاحه من define. هذه الإعدادات باقية للإنتاج فقط؛ QA لا يُهيئ SDK حتى إن مُرر define تفعيل. اختبار telemetry معزول يحتاج دعمًا ومشروعًا منفصلين لاحقًا؛ SENTRY_ENV=qa وحده لا يبدّل المشروع.
- **خدمات وروابط أخرى:** العملات تستخدم Frankfurter ومعطّلة في QA. توجد روابط Unsplash في onboarding وwa.me وStripe وروابط اجتماعات ومحتوى/وسائط في الشاشات. لا يُعاد تفسيرها كبيانات QA موثوقة. مسارات المتصفح وnative media لا تمر كلها عبر ApiClient.
- **الموقع:** VITE_API_URL يضبط API؛ المصدر الحالي يملك fallback مستضافًا عند غياب إعداد الإنتاج. لم تُشغّل نسخة الموقع للتجربة ولم تتغير ملفاتها؛ يلزم env مستقل وegress policy ومراجعة إعداد OAuth إذا دخلت ضمن QA.
- **السيرفر:** MONGODB_URI وJWT_SECRET وCLOUDINARY_* وBREVO/SMTP_* وONESIGNAL_* وGOOGLE_CLIENT_ID والإعدادات المرتبطة بها تحتاج ملفات QA جديدة يوفّرها المالك خارج المصدر. لم تُنسخ credentials من ملفات موجودة ولم يُشغّل server أو seed أو scheduler.

## حدود العزل المهمة

هذا حارس إعداد ونقل API وتفعيل SDKs، **وليس جدار شبكة شاملًا للجهاز**. بعض Image.network والوسائط الأصلية وurl_launcher لا تستخدم هذا النقل، وقد توجد بيانات/رموز قديمة في secure storage وSharedPreferences أو في SDK native على ملف جهاز استُخدم للإنتاج. لا يوجد في هذه المرحلة applicationId منفصل أو ترحيل مفاتيح تخزين أو تبديل تلقائي لهويات الخدمات.

لذلك يبقى **التثبيت واختبار الجهاز محظورين** حتى تُتحقق كل الموارد مع ملف Android جديد معزول/جهاز اختبار غير مستخدم للإنتاج، وتُطبق قائمة خروج شبكة لا تسمح إلا بوجهات QA المقبولة. يجب فحص الوجهات في native/browser أيضًا؛ لا يكفي تمرير define أو نجاح اختبار MockClient. لا تُفعّل QA_RESOURCES_VERIFIED بناءً على الاختبارات المحلية المذكورة هنا.

## التكوين الذي سيُستخدم بعد التحقق فقط

يعتمد المالك عنوان HTTPS QA حقيقيًا منفصلًا، ويتحقق من قاعدة البيانات والتخزين والحسابات وmail sink وعزل الجهاز والشبكة. عند اكتمال ذلك فقط، تُستخدم القيم:

```text
APP_ENV=qa
QA_API_BASE_URL=https://<owner-approved-isolated-host>/api
QA_RESOURCES_VERIFIED=true
```

هذا قالب توثيقي غير صالح للتشغيل، وليس ملف credentials. لا تُمرّر API_BASE_URL كبديل. لا توجد بيانات اعتماد QA مضمّنة أو مُنشأة، ولا اعتماد لنطاق placeholder أو لمجرد اسم يبدأ بـqa.

الاختبارات تستعمل `https://isolated.invalid/api` مع MockClient وtokens وهمية فقط؛ لا DNS أو HTTP إلى ذلك العنوان، وراية التحقق فيها **fixture اختبار** لا إثبات لبيئة حقيقية.
