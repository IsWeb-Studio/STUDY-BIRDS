# Phase 7 — البيئة المحلية المعزولة والاستعداد لأندرويد

التاريخ: 2026-10-21. النتيجة: البيئة المحلية تعمل واختبارات سطح المكتب نجحت؛ لا يوجد APK خاص بـQA ولا اختبار جهاز فعلي، ولا ادعاء بجاهزية الإنتاج.

## ما نُفّذ

- استخدام MongoDB 8.2.6 الموجود مسبقًا دون تنزيل أو تثبيت. قاعدة `studybirds_qa_phase7` تعمل على `127.0.0.1:27029` بالمصادقة وreplica set مستقل. حساب التطبيق محدود بقاعدة QA، واختبار قراءة قاعدة أخرى رُفض فعليًا بالرمز 13.
- تشغيل backend مستقل على loopback فقط: HTTP 5008 وHTTPS 5448. إعداداته وبياناته ومفاتيحه الجديدة في `D:\work\studybirds_qa_phase7` خارج المستودعات وبصلاحيات ملفات مقيدة. تُركت عمليتا البيئة المحلية تعملان؛ لم تُنشأ خدمة Windows.
- تحميل إعداد QA صريح دون قراءة إعداد الإنتاج، ورفض القيم الناقصة أو المجهولة وإعدادات المزودين الخارجيين. حارس شبكة داخل عملية Node يمنع الاتصال الخارجي؛ ليس جدار حماية للنظام أو ضمانًا لشبكة أندرويد.
- بريد وOTP محليان لعناوين `example.invalid` فقط؛ تخزين مستندات محلي وروابط موقعة قصيرة الأجل بعد التحقق من الملكية. تعطيل مسارات المزودين الخارجيين في QA، وعدم تشغيل مهام السيرفر الافتراضية أو migrations.
- seed تراكمي غير ماسح، وحسابات اصطناعية فقط. تكراره أبقى الأعداد وكلمات المرور كما هي: 5 مستخدمين، دولة وجامعة وبرنامج وطلب ومنحة وملف خريج واحد لكل فئة، مستندان، ملفا طالب، وسجل ستوري واحد بقي محذوفًا منطقيًا بعد الاختبار.
- دعم شهادة QA صريحة في عميل Flutter مع التحقق العادي من اسم المضيف، دون قبول جميع الشهادات أو تغيير إعدادات الإنتاج. مستندات QA المحلية تمر عبر حارس الأصل نفسه.
- تعطيل مدخل seed القديم القادر على إعادة ضبط البيانات قبل قراءة البيئة أو الاتصال، في جميع الأوضاع؛ هذا تغيير مقصود في أداة الإدارة القديمة، وليس في API الإنتاج. البديل الجديد مخصص لبيئة QA فقط.

## النتائج الفعلية

- اختبارات إعداد backend: 29 نجاحًا، دون فشل أو تخطي.
- تكامل backend المحلي الحقيقي: 11 نجاحًا، تشمل الصلاحيات وOTP وإعادة استخدام الرمز ورفع/قراءة المستندات وحذف الستوري وتفضيلات الحساب وتجديد الجلسة والخروج وحظر المزودين.
- اختبارات backend الانحدارية المحددة: 16 نجاحًا. لم تُعد الحزمة الكاملة أو اختبارات الموقع؛ ملفات الموقع لم تتغير.
- اختبارات Flutter المحددة: 38 نجاحًا؛ حراس QA والمزودين: 25 نجاحًا؛ اتصال HTTPS المحلي الفعلي وتسجيل الدخول والمستند: اختباران ناجحان على Windows.
- `flutter analyze`: صفر أخطاء وصفر تحذيرات، و275 ملاحظة معلوماتية سابقة؛ exit code 1، لذلك لا يُسجل كفحص نظيف ناجح.
- تعثرت محاولة أولى بسبب مسار ملف defines النسبي، ومحاولة تكامل بسبب بدء الاختبارات قبل جاهزية المستمع. صُحح المسار وأضيف انتظار health موثوق قبل إرسال بيانات الدخول؛ نجحت الإعادات النهائية. السجلات الأصلية محفوظة ولم تُخفَ النتائج الأولية.
- لم يُنفذ build أو تثبيت جهاز أو تنزيل حزم أو migration تبعيات أو نشر أو وصول إنتاج.

## الحفظ والسلامة

نقطة الاسترجاع `.git/phase7-20261021` تحفظ بصمات 1741 ملفًا سابقًا ونسخًا متحققة من الملفات التسعة المعدلة. المقارنة النهائية وحالات Git وبصمة APK ومساحة D موثقة في `PHASE7_VALIDATION.json`. لم تُحذف ملفات المستخدم أو النسخ الاحتياطية، ولم يتغير HEAD أو index أو ارتباط worktree. أسرار QA وOTP لا تظهر في التقارير. أُعيد تشغيل عمليات المساعدة التي أنشأتها هذه المرحلة فقط عند تحديث مصدرها.

**ملاحظة سلامة غير محسومة:** أظهرت المقارنة النهائية اختلاف بصمتي `lib/main.dart` و`lib/app_shell.dart` في التطبيق الأساسي عن بداية المرحلة، إضافة إلى الملفات التسعة المقصودة في تطبيق النشر والسيرفر. الفروق الظاهرة تعيد تجميع الاستيرادات عبر `screens/screen.dart` و`core/core_import.dart`. لا تُنسب تلقائيًا إلى Phase 7؛ لم تُستبدل أو تُرجع، ولم يُختبر أثرها في التطبيق الأساسي. لذلك لا يصح إعلان أن جميع مصادر التطبيق الأساسي بقيت دون تغيير. توقفت تعديلات المصدر، وتحتاج هذه الفروق مراجعة صاحب العمل قبل توحيد النسخ أو أي إصدار. نتائج Flutter المذكورة تخص تطبيق النشر المنفصل.

المساحة المقاسة قرب الإنهاء نحو 5.52 GiB؛ لم يُجرَ تنظيف جديد. لا تكفي لاعتماد بناء Flutter مضبوط وفق هامش 6 GiB المخطط، ويلزم قياس جديد قبل أي بناء لاحق.

## ما يمنع الانتقال للجهاز

1. تحديد جهاز/محاكي QA معزول وإثبات عدم وصوله للإنتاج. التطبيق يحمل `com.studybirds.app` وروابط `autoVerify` للنطاق الإنتاجي؛ ملف مستخدم Android منفصل وحده لا يضمن عزل حزمة التطبيق.
2. اعتماد استراتيجية applicationId/manifest/output منفصلة أو جهاز مخصص بشروط شبكة مثبتة. لم تُطبق تعديلات native أو flavor جديدة.
3. اعتماد اتصال USB عبر ADB reverse والثقة بالشهادة. لم تُشغّل أوامر ADB أو يُثبت شيء على جهاز. مسارات الصور والفيديو والمتصفح الأصلية تحتاج تحققًا مستقلًا، كما أن تعطيل المزودين في Dart لا يثبت تعطيل كل تهيئة native.
4. توفير هامش قرص ومسار بناء يحفظ APK القديم دون استبداله حتى مؤقتًا. ملف defines المستخدم لاختبارات Windows ليس إعدادًا معتمدًا لبناء APK.
5. أي OAuth أو push أو مزود خارجي مطلوب يحتاج موارد QA مستقلة وموافقة منفصلة. لم تُنشأ أو تُغيّر إعدادات مزود مستضاف.
